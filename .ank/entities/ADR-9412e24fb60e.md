## Context

ADR-47ac4cc86c43 was ratified on 2026-10-11 and has no code behind it
(measured 2026-10-14, c859d01f: `ank help` lists no `signers`, and
TASK-415a811ef416 is open). It adds a verb that reads a principal's signing
keys from GitHub through `gh api` and writes the difference into `signers:`.

What it buys is one copy-paste avoided per new machine. What it costs is a
verb of the binary whose answer depends on a forge, a `github:` field in the
corpus's configuration naming an account on that forge, a dependency on `gh`
being installed and authenticated, and a stub of `gh` in the test suite. The
thesis of ADR-9a0076dd0896 names the fourth property ank rests on, a corpus
that lives whole in the clone with no service between an agent and it, and a
verb that reads GitHub serves none of the four.

ADR-5c6db7a161b8 is the decision that matters here and it stands whole: keys
live in `config.yml`, `ank signers` writes them, a lost key is retired by date
rather than removed, and `check` judges ratifications offline. Four keys in two
months for one maintainer is the measured need, and `ank signers add` answers
it with the same pull request the sync would have produced.

## Decision

The sync is withdrawn. `signers:` carries keys, notes and `valid_before`, and
no `github:` login. `ank signers` has four subcommands, add, retire, remove and
migrate. No verb reads a forge.

## Consequences

- TASK-415a811ef416 is closed with this decision as its reason.
- SPEC-14cd3e35e927, proposed, lists `ank signers <add|retire|remove|migrate>`.
- `docs/signing.md` describes declaring a key by hand and nothing else.
- A team that wants its keys mirrored from a forge writes the integration
  outside the binary, the way a pipeline writes `attest` (ADR-493471d64ba0).

## Rejected

- **Keeping sync as an explicit network act.** ADR-64f32c74a0f9 admits one
  such verb, `update`, because replacing the binary cannot be done offline.
  Copying a public key can.
