The one piece of the GRAPH screen that is pure arithmetic, so it is cut out to be tested without a terminal and written beside no view code.

The reference is `git log --graph`, and a working implementation of the lane walk exists outside this repository (tools/ank-viz/ankviz.py in a sibling project, `layout_graph`): topological order first, then one pass over the rows keeping a vector of lanes, each lane holding the id it is waiting for. A node takes the lane waiting for it, or the first free lane; its first blocker continues that lane, each further blocker takes a free lane -- unless a lane is already waiting for that blocker, in which case the edge joins it, which is the merge. A lane freed is reused, and the trailing free lanes are dropped so the width is what the rows need.

What this module does not decide: which nodes are shown (the view folds history) and which order breaks ties (the view hands in the listing's own order, the work that is alive first and then the most recently created, so that an identifier orders nothing, ADR-559eebf5c6f5). It also does not paint: colour belongs to the shared table and the row composer, and ADR-559eebf5c6f5 requires the frame with paint and without it to be identical character for character, which a module that emits characters only cannot break.

Measured on this corpus on 2026-10-14: 501 tasks, 210 edges, 260 tasks with no edge at all, the widest fan 7 blockers on one task and 8 dependents on another. A layout over everything is a few hundred rows and a dozen lanes; over the open work (12 tasks) it is a handful.
