The test enters a named second at its start and relies on one `ank context`
finishing inside that second, so the renewal computes the expiry already on
the ref. Under load it does not: on 2026-10-14 the worker of TASK-0c23 saw it
fail three times while another agent ran the suite, and pass alone. A test
whose outcome depends on the runner's speed is a timing assertion in disguise,
which CLAUDE.md rules out ("prove a process cost by counting processes and
never by timing"). The fix is to control the clock the binary reads rather
than racing it.
