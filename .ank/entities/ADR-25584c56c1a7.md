## Context

SPEC-1d5b44efd388 section 10 defers `enforced_by` as "the underlying mechanism
against context inflation", with the reason "useless while the ADR corpus is
small", and section 11 describes the sink: a rule born in prose becomes either
a scoped ADR that `context` serves or a mechanised check, once it binds daily
work.

Measured on 2026-10-14 (c859d01f): `check` reports 12 over-constrained
scopes, the largest at 49 638 characters of constraint against a limit of
4 000, up from 18 745 on 2026-08-23 when ADR-6e09f8a67540 priced perimeters at
creation to stop the growth. `ank context crates/ank-cli/src/human.rs` names
26 constraints. In orientation mode the page spends a third of the budget on
them and names them by title; in execution mode, the moment an agent holds a
claim and is about to edit, every one is served whole: 28 617 characters, in
the JSON an agent reads. The corpus is no longer small, and the trigger has
fired.

Most of those 26 are already held by something mechanical. The process count
of ADR-cc65f1388a71 is a test. The contract of ADR-6fd69efb629c is golden
fixtures. The listings of ADR-3e6ce108edcd are tested. The round-trip of
ADR-63b59c5c26f7 is the golden suite. An agent handed their full text is
handed a rule a test will enforce whether or not the agent read it, and the
budget that text consumes is taken from the rules nothing but the agent
enforces.

## Decision

An ADR names what holds it: `enforced_by`, a list of `<path>#<symbol>`
entries, a tracked file and a symbol it contains, a test function, a verifier
name in a workflow, a check rule. `check` confronts both halves with the tree,
the way a scope is confronted (ADR-3094538d831e): a dead path or an absent
symbol is a signal naming the entry, never a fault, because a renamed test is
not a broken rule.

`context` serves such an ADR by its title, one line with its entries, in both
modes. The rule still binds, the line still says so, and an agent that wants
the text runs `ank show`. The over-constrained charge stops counting it, since
the text is no longer what the agent is handed.

The field sits outside the ratification anchor, which covers `constraint` and
`scope` and nothing else (`ratification_anchor` in human.rs), so `amend` writes
it on an accepted ADR exactly as it writes `amends` today, and no supersession
is needed to declare what already holds a settled rule. That is what makes
this reach the 26 rather than only the rules written after it.

## Consequences

- One optional field on the ADR kind, in the registry, the model, the parser,
  a golden fixture, docs/format.md and docs/entity-fields.md; no schema bump,
  as for `amends` and `method`: an older build refuses the field loudly and
  never drops it in silence.
- `--enforced-by` on `new adr` and `amend`, `--drop-enforced-by` on `amend`.
- A task walks the ADRs covering `crates/ank-cli/src/human.rs` and declares
  what holds each, with the charge measured before and after.
- The row in SPEC-1d5b44efd388 section 10 is marked fired by the successor of
  that spec.

## Rejected

- **A free-text `enforced_by`.** An identifier in prose is not a reference
  (ADR-1e6bcbf62e61); a path and a symbol can be confronted with the tree.
- **Deriving enforcement from test names.** The tool would guess, on names
  that drift; the author of the rule knows which test holds it.
- **Serving a mechanised rule nowhere.** It binds, and an agent must be able
  to learn that it exists without reading the test suite.
- **Lowering the charge by raising `context_budget`.** ADR-6e09f8a67540
  already refused that: the six precise scopes sit at 4 415, where a healthy
  perimeter sits.
