 print 'bash.exe: warning: could not find /tmp, please create!' (once or twice), which is the output that hashed to 178beb259302 and 34e87002d44e; doc_replay alone on the same runner: output empty, 23 passed (run 38404856286). The runner TEMP C:\Users\RUNNER~1\AppData\Local\Temp never disappeared: a 100ms watcher over the whole suite recorded no transition (run 38407403256, still 2 failed). Cause: Git for Windows mounts /tmp as usertemp, resolved from the TEMP of the first MSYS process and held in memory shared by every MSYS process of the installation while any of them lives; nextest keeps the suite's sh children overlapping, so the mount stays pinned to a test's scratch TEMP (ank-it-<pid>) after the scratch sweeper removed it. Experiment: one long-lived MSYS process (Git\usr\bin\sleep.exe) started with the runner TEMP before the suite -> 1501 passed, 0 failed, no /tmp warning (run 38409441075). Not reproduced locally because an interactive Git Bash always holds the mount there, and the cargo-test verifier's own sh -c holds it during ank done. Fix: the CI test step runs under shell: bash, which is that long-lived process. The regression test is doc_replay's proof_replays and quickstart_replays: red without the fix (runs 38398699531 twice, 38405266482, 38407403256), green with it on the run of this branch.
